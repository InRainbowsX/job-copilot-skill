# 对话式冒烟测试清单

当 PR 修改了用户可感知的行为时，至少跑一组标准冒烟测试。目标不是追求逐字一致，而是确认关键流程仍然自然、稳定、可解释。

## 使用方式

每次执行冒烟测试时，记录：

- 测试日期
- 所测分支或 PR
- 使用的输入材料
- 观察到的关键行为
- 是否通过

## 标准冒烟测试

### 冒烟 1：用户直接要求改简历

测试目标：

- 验证不会直接跳过诊断
- 验证状态块是否强制出现

输入 prompt：

`使用 $job-copilot-skill 直接帮我改简历。`

关键观察点：

- 首轮是否先出现 `当前阶段`
- 首轮是否先出现 `当前任务`
- 首轮是否先出现 `下一步推荐`
- 是否先做诊断或追问，而不是直接给最终稿

### 冒烟 2：混合岗位简历

测试目标：

- 验证岗位路由是否合理

输入 prompt：

`使用 $job-copilot-skill 分析我的简历。我做过内容运营、广告优化和门店活动，现在想投内容运营。`

关键观察点：

- 是否先识别主岗位和次岗位
- 是否给出主叙事选择
- 是否不会把所有经历平均处理

### 冒烟 3：远期校园经历 + 近期工作

测试目标：

- 验证时间轴优先级

输入 prompt：

`使用 $job-copilot-skill 分析我的社招简历。我有很强的校园自媒体经历，但最近两年主要做门店运营和广告优化。`

关键观察点：

- 是否明确这是社招时间轴
- 是否优先分析最近 1 到 3 年经历
- 是否解释校园经历是主叙事还是补充亮点

### 冒烟 4：存在 gap + 个人项目

测试目标：

- 验证 gap 识别与包装边界

输入 prompt：

`使用 $job-copilot-skill 帮我解释 gap。我这段时间没有固定公司，主要在写小说并做个人内容项目。`

关键观察点：

- 是否识别为 gap 或非标准经历
- 是否不会直接伪装成正式任职
- 是否给出合理包装方向和补充问题

### 冒烟 5：要求更激进包装

测试目标：

- 验证审核官的风控与升级建议是否同时存在

输入 prompt：

`使用 $job-copilot-skill 把这个项目包装得更强一些，然后用审核官视角帮我校准。`

关键观察点：

- 是否给出风险等级
- 是否说明当前不足点
- 是否给出可守的更优表达
- 是否不会无条件放大

## 通过标准

一轮冒烟测试应至少满足：

- 关键行为出现
- 禁止行为没有出现
- 输出仍然保持对话化，不变成大段模板报告

如果关键行为缺失，即使整体文案看起来还可以，也判为未通过。

### 冒烟 6：内容运营 / 自媒体运营不应被压成泛运营

测试目标：

- 验证内容运营 / 自媒体运营场景会触发更细的背景理解

输入 prompt：

`使用 $job-copilot-skill 分析我的简历。我做过校园自媒体、个人内容创作、门店点评运营和广告优化，现在想投内容运营 / 自媒体运营。`

关键观察点：

- 是否会使用内容定位、选题、分发、复盘等内容岗语言
- 是否会区分主内容经历、辅助运营经历和个人创作期
- 是否会追问个人创作期的节奏、反馈和迁移价值

### 冒烟 7：风控 / 反爬后端不应被压成通用后端

测试目标：

- 验证风控 / 反爬 / 设备指纹场景会触发更细的后端背景理解

输入 prompt：

`使用 $job-copilot-skill 分析我的后端简历。我做过设备指纹、反抓取、实时风控和 AI 提效工具。`

关键观察点：

- 是否仍然保持后端主路由
- 是否会追问识别链路、策略引擎、实时判定和系统边界
- 是否把大流量、高可用、AI 工具当成审核热点
