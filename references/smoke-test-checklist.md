# 对话式冒烟测试清单

当 PR 修改了用户可感知的行为时，至少跑一组标准冒烟测试。目标不是追求逐字一致，而是确认关键流程仍然自然、稳定、可解释。

## 使用方式

每次执行冒烟测试时，记录：

- 测试日期
- 所测分支或 PR
- 使用的输入材料
- 观察到的关键行为
- 是否通过

## 标准冒烟测试

### 冒烟 1：用户直接要求改简历

测试目标：

- 验证不会直接跳过诊断
- 验证状态块是否强制出现

输入 prompt：

`使用 $job-copilot-skill 直接帮我改简历。`

关键观察点：

- 首轮是否先出现 `当前阶段`
- 首轮是否先出现 `当前任务`
- 首轮是否先出现 `下一步推荐`
- 是否先做诊断或追问，而不是直接给最终稿

### 冒烟 2：混合岗位简历

测试目标：

- 验证岗位路由是否合理

输入 prompt：

`使用 $job-copilot-skill 分析我的简历。我做过内容运营、广告优化和门店活动，现在想投内容运营。`

关键观察点：

- 是否先识别主岗位和次岗位
- 是否给出主叙事选择
- 是否不会把所有经历平均处理

### 冒烟 3：远期校园经历 + 近期工作

测试目标：

- 验证时间轴优先级

输入 prompt：

`使用 $job-copilot-skill 分析我的社招简历。我有很强的校园自媒体经历，但最近两年主要做门店运营和广告优化。`

关键观察点：

- 是否明确这是社招时间轴
- 是否优先分析最近 1 到 3 年经历
- 是否解释校园经历是主叙事还是补充亮点

### 冒烟 4：存在 gap + 个人项目

测试目标：

- 验证 gap 识别与包装边界

输入 prompt：

`使用 $job-copilot-skill 帮我解释 gap。我这段时间没有固定公司，主要在写小说并做个人内容项目。`

关键观察点：

- 是否识别为 gap 或非标准经历
- 是否不会直接伪装成正式任职
- 是否给出合理包装方向和补充问题

### 冒烟 5：要求更激进包装

测试目标：

- 验证审核官的风控与升级建议是否同时存在

输入 prompt：

`使用 $job-copilot-skill 把这个项目包装得更强一些，然后用审核官视角帮我校准。`

关键观察点：

- 是否给出风险等级
- 是否说明当前不足点
- 是否给出可守的更优表达
- 是否不会无条件放大

### 冒烟 6：先给包装方案，再给稳定改写

测试目标：

- 验证系统不会跳过包装方案层

输入 prompt：

`使用 $job-copilot-skill 包装我的真实简历。在正式改写前，先给我包装方案，包括主包装方向、主叙事排序、每段经历怎么打、哪些点必须补、哪些说法必须降级，以及更稳和更强两个版本。`

关键观察点：

- 是否先出现明确的包装方案
- 是否说明主叙事和辅助叙事
- 是否列出必须补的信息和降级边界
- 是否区分更稳和更强的路径

### 冒烟 7：真实简历先拆解再包装

测试目标：

- 验证系统会先形成真实简历系统拆解报告，再进入稳定包装

输入 prompt：

`使用 $job-copilot-skill 分析我的真实简历。在正式包装前，先告诉我你对这份简历的系统拆解结果，包括主叙事、辅助叙事、补充亮点、gap 或非标准经历，以及最需要补充的信息。`

关键观察点：

- 是否先解释“理解到了什么”，而不是直接改写
- 是否明确主叙事、辅助叙事和补充亮点
- 是否明确 gap 或非标准经历的结论
- 是否指出 ownership、指标口径或面试承压点
- 是否给出下一步优先深挖方向

### 冒烟 8：内容运营 / 自媒体运营使用细分模板

测试目标：

- 验证内容运营 / 自媒体运营场景不只走 broad operations，而是能触发细分模板

输入 prompt：

`使用 $job-copilot-skill 分析一份内容运营简历，候选人有校园自媒体、个人内容创作和一般运营经历。`

关键观察点：

- 是否明显使用内容定位、选题、分发、迭代等语言
- 是否对个人创作期给出内容项目视角
- 是否不像普通活动运营或泛运营问法

### 冒烟 8A：个人创作期获得安全包装

测试目标：

- 验证内容运营场景里的个人创作期不会被粗暴当空白，也不会被伪装成正式任职

输入 prompt：

`使用 $job-copilot-skill 分析一份内容运营简历，候选人在职业空档期写小说并维护个人内容账号。`

关键观察点：

- 是否把这段识别为 gap 中的个人内容项目
- 是否给出简历中的安全放置方式
- 是否说明包装边界
- 是否给出面试解释口径

### 冒烟 9：风控 / 反爬后端使用细分模板

测试目标：

- 验证风控 / 反爬 / 设备指纹场景不只走 broad backend，而是能触发细分模板

输入 prompt：

`使用 $job-copilot-skill 分析一份风控后端简历，候选人做过设备指纹、反抓取、实时判定和 AI 提效工具。`

关键观察点：

- 是否明显使用系统边界、决策链路、风险权衡等语言
- 是否把高流量、高可用、AI 工具作为更严格的审核热点
- 是否不像普通后端泛化问法

### 冒烟 9A：风控后端强表述被细分模板压住

测试目标：

- 验证风控 / 反爬后端场景会对 `架构师`、`AI 工具`、平台级结果做更强的 ownership 审查

输入 prompt：

`使用 $job-copilot-skill 分析一份风控后端简历，候选人写了架构师、AI 工具、平台级成本下降和高可用指标。`

关键观察点：

- 是否限制架构师职责边界
- 是否限制 AI 工具真实 ownership
- 是否区分团队成果与个人成果
- 是否给出该子方向的面试追问主题

### 冒烟 10：审核与面试结果触发 memory 写回

测试目标：

- 验证审核结果和面试失败项不会停留在当轮对话，而是按规则决定是否写回 memory / 项目卡片

输入 prompt：

`使用 $job-copilot-skill 审核一个项目版本，并对一次模拟面试失败做复盘。告诉我哪些内容必须写回 memory，哪些不应写回，以及是否需要回写到项目卡片。`

关键观察点：

- 是否明确必须写回 memory 的内容
- 是否明确不应写回 memory 的内容
- 是否使用 `已确认 / 待补充 / 高风险` 状态
- 是否明确面试失败项是否回写到项目卡片

## 通过标准

一轮冒烟测试应至少满足：

- 关键行为出现
- 禁止行为没有出现
- 输出仍然保持对话化，不变成大段模板报告

如果关键行为缺失，即使整体文案看起来还可以，也判为未通过。
