# Gap Option Library

用于回答这类问题：

- `gap 期能补什么真实内容`
- `没有社保记录时，哪些经历可以安全地写进简历`
- `我想补个人项目、内容项目、写作项目，哪些更适合当前岗位`

核心原则：

- 先保证真实，再讨论包装强度
- 先判断它在简历里的位置，再讨论怎么写
- 目标是解释 gap、补能力信号、降低风险，不是伪造正式任职

## 使用顺序

1. 先识别 gap 类型：学习型、项目型、创作型、兼职型、混合型、照护型
2. 再判断目标岗位：内容运营、商家运营、HR Ops、技术岗等
3. 再从下面选最贴岗位、最好举证、最能讲住的一类
4. 输出时必须同时说清：
   - 建议放在 `个人项目 / 补充经历 / gap 说明 / 作品集`
   - 最低支撑材料
   - 高风险误写方式

## 优先级分层

- `A 档`：最适合写进简历，能明显补能力信号
- `B 档`：可写，但更适合做补充项
- `C 档`：仅适合做解释，不适合当核心亮点

## 选项清单

|---|---|---|---|---|---|---|

## 角色偏好

### 内容运营 / 新媒体运营

优先考虑：

- 个人内容账号/栏目
- 行业观察/专题写作
- 作品集/案例集项目
- 小型商业化内容尝试

不建议优先：

- 纯情绪日记式写作
- 没有持续更新记录的“准备做账号”

### 商家运营 / 本地生活运营

优先考虑：

- 商家/门店诊断项目
- 个人内容账号，但内容主题要围绕餐饮/本地生活
- 兼职协助门店、活动、投放或客服支持

### HR Ops / SSC / 员工关系

优先考虑：

- 制度/流程梳理案例集
- 人事表单、FAQ、SOP、政策解读样稿
- 合规政策梳理、员工服务文档类产出

不建议优先：

- 与员工服务完全无关的泛内容项目

## 推荐输出格式

当用户问“gap 期可以补什么”时，优先输出：

1. 最适合当前目标岗位的 `2-4` 个选项
2. 每个选项在简历里的位置
3. 每个选项最低需要什么证据
4. 哪个是最稳妥的主推方案

## 不允许做的事

- 伪造公司、职位、团队或汇报线
- 把个人项目伪装成全职任职
- 用没有支撑的数据写成果型项目
- 把 `准备做` 写成 `已经做成`

## 一句判断模板

- `这个选项适合放在个人项目，用来补 gap 和补内容信号，但不能替代最近正式经历。`
- `这个选项只能做解释，不适合当主项目，因为可验证结果太弱。`
- `这个选项和目标岗位衔接最好，前提是你能补出最基本的产出记录和复盘。`
