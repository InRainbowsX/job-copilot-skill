# 风控 / 反爬后端背景知识库

本知识库用于帮助 `简历包装教练` 和 `审核官` 在后端主路由下，正确理解风控 / 反爬 / 设备指纹这类高风险子方向。

## 1. 角色定位

风控 / 反爬不是独立于后端之外的另一套岗位，而是 `后端 / 服务端` 的一个高风险、高对抗、强实时子方向。

在这个方向里，候选人通常需要同时体现：

- 实时系统能力
- 高并发或低延迟处理能力
- 风险识别或对抗链路理解
- 策略、识别、数据和决策系统之间的边界感

因此，包装时主路由仍然应是 `后端 / 服务端`，子标签才是：

- 风控
- 反爬
- 设备指纹 / 设备智能
- 安全对抗

## 2. 常见系统边界

这个子方向常见的系统边界包括：

- `设备识别 / 设备指纹`：收集设备、浏览器、环境或行为特征，形成稳定识别信号
- `Bot / anti-crawl detection`：利用指纹、行为分析、挑战策略、机器学习或规则识别自动化流量
- `风险识别 / 实时判定`：将多维信号在低延迟条件下汇总为风险分或决策结果
- `规则引擎 / 策略引擎`：维护可配置规则、阈值、策略实验和上线节奏
- `反馈闭环`：把处置结果、误杀/漏放结果、人工反馈或案件数据回流到模型、规则和特征

对外部官方资料的抽象共识包括：

- Cloudflare 明确把 bot detection 建立在 `machine learning + behavioral analysis + fingerprinting` 上
- Fingerprint 的官方资料强调服务端使用 device intelligence / smart signals 做 fraud prevention，而不是只看前端单点识别

## 3. 强候选人信号

这个方向里更强的简历信号通常是：

- 能说清系统在整个风控/反爬链路里的位置
- 能说清实时性要求、吞吐规模、可用性目标或成本约束
- 能解释信号采集、识别、判定、处置和反馈的边界
- 能说明策略、规则、算法和工程系统如何协同
- 能区分 `系统级结果` 和 `个人 ownership`

更高级的强信号：

- 有攻防视角，而不是只有“做了个服务”
- 能说明误杀、漏放、覆盖率、召回或经济损失之间的权衡
- 能解释为什么某个识别链路要同步、异步、缓存或降级
- 能把模型、规则、指纹、挑战或人工复核放进一个完整决策闭环里讲

## 4. 成果表达策略

这个方向的结果，不应只写“大流量、很稳定”。

更稳的结果维度包括：

- latency：判定延迟、TP99、实时路径耗时
- throughput：QPS、峰值请求量、批量分析吞吐
- availability：可用性、恢复时间、降级稳定性
- quality：拦截效果、误杀率、漏放风险、识别覆盖
- efficiency：机器成本、存储成本、计算成本、人工审核成本
- business / risk impact：减少欺诈损失、降低被爬风险、提升正常用户体验、降低 captcha 或挑战干扰

表达要求：

- 指标必须有上下文，不要孤立报数字
- 尽量说明观察周期、系统范围和计算口径
- 团队级收益要和个人贡献拆开

## 5. 高风险表述边界

这个方向最容易过度包装的点包括：

- `架构师`：如果只是承担部分模块设计或主实现，不应直接写成全局架构 owner
- `整体架构设计`：必须先讲清边界，否则容易虚高
- `亿级流量 / 超低延迟 / 高可用`：没有链路范围和口径，都会变成高风险数字
- `AI 工具提效 / AI 自动识别`：如果只是接入、试点或辅助使用，不能包装成成熟核心能力
- `风控收益`：减少损失、降低误杀等结果若无明确口径，面试里很容易被击穿

## 6. 简历包装时应优先追问什么

`简历包装教练` 应优先追问：

- 这个系统在整个风控 / 反爬架构里的边界是什么
- 你负责的是采集、识别、判定、处置还是反馈中的哪一段
- 为什么要做同步或异步拆分
- 延迟、吞吐、可用性要求是什么
- 哪个指标是系统最关键的 success metric
- 你的个人 ownership 到底是模块级、链路级还是系统级
- 遇到过哪些真实的误判、漏判、攻击对抗或系统故障

## 7. 审核时应重点看什么

`审核官` 要重点检查：

- 是否还能解释系统边界，而不是只会背术语
- 是否把策略、识别、模型和工程系统混为一谈
- 是否把团队级架构或平台结果直接写成个人 ownership
- 是否能解释高流量、高可用、低延迟指标的范围和口径
- 是否把 AI 工具写得比真实成熟度更高

## 8. 常见弱表述与更强方向

常见弱表述：

- 负责风控系统建设
- 搭建反爬平台，提升拦截效果
- 设计设备指纹方案，保障系统稳定

更强的包装方向：

- 讲清系统在业务链路里的位置
- 讲清识别 / 判定 / 处置链路和关键权衡
- 讲清延迟、吞吐、稳定性或成本目标
- 讲清结果与风险边界

## 9. 可引用的外部信号来源

以下公开产品与官方资料强化了本知识库的判断方向：

- Cloudflare Bot Management 官方资料强调 `machine learning`、`behavioral analysis`、`fingerprinting` 共同识别恶意 bots，并关注 content scraping、credential stuffing 等场景
- Fingerprint 官方 Smart Signals 文档强调服务端使用 device intelligence、bot detection、browser tampering、VPN 等信号进入 fraud prevention logic

这些资料共同说明：这类简历真正值钱的，不是堆几个“风控”“AI”“反爬”词，而是把 `信号采集 -> 识别判定 -> 实时决策 -> 反馈优化` 的工程链路讲清楚。
