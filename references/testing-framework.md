# 测试框架

这个仓库是一个 skill 项目，不是传统应用。验证不能只证明结构合法，还要证明规则在真实对话里会生效。

## 设计原则

这套测试框架主要吸收了以下公开思路：

- Anthropic 的测试与评测文档：先定义成功标准，再选合适的验证方式
- Anthropic 的 eval tool 思路：将测试集做成可重复复用的用例，而不是临时试一次
- Antigravity 的 skill 写法：先写失败场景，再补 skill 规则
- Promptfoo 的 prompt 测试方式：用输入、断言和回归集管理行为变化

对应到本仓库，核心原则是：

- 先定义行为成功标准，再改 skill
- 规则变更必须有可重复验证的用例
- 能做结构断言时，不先依赖主观感受
- 修过的问题要进入回归集，避免旧问题返回

## 测试分层

### 1. 静态检查

目的：

- 验证仓库结构
- 验证关键文件存在
- 验证 `SKILL.md` 合法

主命令：

```bash
./scripts/run_checks.sh
```

这一层只能证明仓库形态正确，不能证明对话行为正确。

### 2. 规则用例测试

目的：

- 一次只验证一个规则单元
- 判断某个行为是否在输出中出现
- 让规则修改具备可审查性，而不是只能靠完整长对话试用

典型目标：

- 状态块必须出现
- 社招时间轴下最近经历优先
- 简历包装教练必须先诊断再追问
- 审核官输出必须带风险和升级建议
- gap 期不能被直接伪装成正式任职

使用文件：[rule-test-cases.md](./rule-test-cases.md)

### 3. 对话式冒烟测试

目的：

- 快速验证关键流程在真实 prompting 下仍然自然可用
- 发现“规则写进去了，但真实输出没有显现”的问题

冒烟测试使用少量高价值 prompt，重点看关键观察点，不追求逐字一致。

使用文件：[smoke-test-checklist.md](./smoke-test-checklist.md)

### 4. 回归测试

目的：

- 保留已经修过的问题
- 阻止旧问题静默回归

凡是真实出现过、且被修复过的行为问题，都应该评估是否进入回归集。

使用文件：[regression-cases.md](./regression-cases.md)

## 何时使用哪一层

| 变更类型 | 必做验证 |
|---|---|
| 只改仓库结构或治理文件 | 静态检查 |
| 修改核心流程行为 | 静态检查 + 规则用例 + 冒烟测试 |
| 修复已经出现过的行为问题 | 静态检查 + 回归集更新 |
| 调整 prompt / rule 且影响用户可见输出 | 静态检查 + 规则用例 + 冒烟测试 |
| 修改路由、包装、排序等判断逻辑 | 静态检查 + 规则用例 + 定向冒烟测试 |

## 评审要求

对于行为变更类 PR，评审时默认期待看到：

- `./scripts/run_checks.sh`
- 必要时更新 `references/validation-scenarios.md`
- 规则变更时更新规则用例
- 影响真实对话时更新冒烟测试清单
- 修复真实 bug 时补回归案例

仅有静态检查，不足以证明高信号行为修改已经生效。
