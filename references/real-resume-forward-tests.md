# 真实简历前向验证

本文件使用真实简历材料做前向验证，重点不是追求最终文案逐字一致，而是验证 Job Copilot 是否真的能：

- 做对岗位路由
- 遵守时间轴优先级
- 识别 gap 与非标准经历
- 让简历包装教练先诊断再追问
- 让审核官拦截过度包装并给出升级建议
- 在真实材料上保持可解释、可面试、可持续迭代

## 用例 1：张雪琴（内容运营 / 新媒体运营）

### 候选人快照

- 年龄 24，本科市场营销
- 最近经历：
  - `2024.07-至今` 知乎短篇小说创作与市场洞察
  - `2023.04-2024.07` 北京欣欣向阳花，点评运营
  - `2022.06-2023.03` 上海云趣，广告优化运营
- 远期亮点：
  - `2018.12-2021.12` 校园自媒体创业，QQ/微信/论坛矩阵

### 预期岗位路由

- 主路由：`运营`
- 更细分的主方向：`内容运营 / 新媒体运营 / 自媒体运营`
- 次路由：`广告运营` 或 `用户增长 / 活动运营`

### 关键验证点

1. 不能把她粗暴处理成“泛运营”
2. 不能只因为校园自媒体更亮就直接把它定为当前主叙事
3. 必须识别 `2024.07-至今` 这段“知乎短篇小说创作”属于 gap 中的非标准经历或个人内容项目
4. 简历包装教练要先解释：
   - 当前主叙事应该如何选
   - 哪段经历最值得深挖
   - 哪段经历只能做补充亮点
5. 审核官要能指出：
   - 校园自媒体数据口径风险
   - 点评运营里多项指标缺基线
   - 广告优化经历职责边界过泛

### 通过标准

- 明确这是 `2026-03-29` 时点下的社招分析
- 明确区分：
  - 当前主叙事
  - 支撑项目
  - 补充亮点
- 明确说明“知乎创作期”不是正式任职，但也不是裸空窗
- 对校园自媒体经历做时间降权，同时保留其内容运营信号价值
- 审核官能给出可守的降级与升级建议

### 这个用例暴露出的短板

- 现有 `operations` 模板对“内容运营 / 自媒体运营”还是偏泛，缺少更细的内容生产、选题机制、平台差异和个人创作期包装规则
- 现有规则对“正在进行中的个人创作 / 内容项目”虽能识别为 gap 或非标准经历，但缺少更具体的内容岗写法与面试解释策略
- 包装结果必须进一步明确：这类经历在简历中的安全放置方式、包装边界以及面试解释口径

## 用例 2：王旭（后端 / 风控 / 反爬）

### 候选人快照

- 本科 211，通信工程
- 最近经历：
  - `2025.06-至今` 去哪儿，后端 Java / 反爬
  - `2021.03-2025.06` 58，同期包含设备指纹与反抓取系统，岗位写作“后端 / 架构师”
  - `2018.07-2021.03` 中兴，Linux 平台研发

### 预期岗位路由

- 主路由：`后端 / 服务端`
- 次标签：`风控 / 反爬 / 安全对抗`

### 关键验证点

1. 必须先识别为后端，而不是被“风控 / 安全 / AI 工具”关键词带偏
2. 要能识别这是高强度技术简历，不该只做泛化措辞优化
3. 简历包装教练要优先深挖：
   - 设备指纹整体架构
   - 反抓取系统体系化建设
   - 去哪儿设备风控与 AI 提效工具
4. 审核官要重点检查：
   - “架构师”职责是否有足够支撑
   - 超大流量和高可用指标是否有上下文
   - AI 提效与漏洞探测是否能讲清真实边界
   - 团队级成果与个人 ownership 是否被混写

### 通过标准

- 明确主路由为后端，不偏成“泛安全岗”
- 明确主叙事按最近高价值系统来组织，而不是把所有项目平均对待
- 包装结果能体现系统边界、技术挑战、性能/稳定性结果和权衡
- 审核官能指出“架构师”“整体设计”“AI 工具落地”等高风险表述的承压点
- 模拟面试主题应自然落到：
  - 风控体系
  - 设备识别
  - 分层反爬
  - 高并发与低延迟

### 这个用例暴露出的短板

- 现有后端模板足够覆盖通用服务端，但对 `风控 / 反爬 / 设备指纹 / 安全对抗` 这类高风险子方向还不够细
- 当前高质量信号库中的后端部分偏通用，对“风控后端”的业务与攻防信号覆盖不足
